🗺️ O ciclo plan → exec → review

4 etapas, 4 papeis. Memorize esse ciclo — e o "padrao de fabrica" que cobre 80% das features.

  1. 1. Plano (GPT-5.5): produz markdown com lista de arquivos, schema, ordem, riscos. Salva em PLAN.md.
  2. 2. Refino (Opus): le PAGES.md/COPY, sugere copy, microcopy, hierarquia. Salva em UX.md.
  3. 3. Implementacao (DeepSeek): le PLAN.md + UX.md, gera codigo. Faz commits incrementais.
  4. 4. Revisao (GPT-5.5/Opus): le PLAN + diff, retorna checklist. Aprova ou volta para etapa 3.
2

🎯 Sinais para sair do executor

DeepSeek travou em loop, fez 3 tentativas erradas, ou esta inventando API que nao existe — pare. Suba para GPT-5.5 com o contexto.

🚨 Gatilhos para escalar

  • • Mesma falha de teste depois de 2 tentativas
  • • Codigo cita biblioteca/funcao que nao existe
  • • Saida divergiu do plano sem justificar
  • • Voce esta tendo que "guiar passo a passo"
  • • Modelo perguntou "sera que devo X?" — sinal de duvida sobre o problema
3

🧭 Cheat sheet: tarefa → modelo

Imprima e cole na parede. Em 1 semana voce internaliza e nao precisa mais consultar.

SituacaoModelo
"Preciso pensar em arquitetura"GPT-5.5
"Implementa este plano detalhado"DeepSeek
"Critique meu UX"Opus
"Bug aleatorio em producao"GPT-5.5
"Reescreve em outra linguagem"DeepSeek
"Auditar este diff"GPT-5.5
4

🔁 Loops de revisao quando algo da errado

Bug de implementacao = volta para etapa 3. Bug de plano = volta para etapa 1. Maioria dos devs reescreve tudo — voltar para a etapa certa economiza 80% do retrabalho.

🔧 Diagnostico

  • Codigo nao funciona como esperado → volta para etapa 3 com correcao especifica
  • Codigo funciona mas resolve o problema errado → volta para etapa 1 (plano errou)
  • UX confuso → volta para etapa 2 (designer revisita)
  • Muitos bugs descobertos por usuarios → ajustar etapa 4 (revisao mais rigorosa)
5

⚡ Atalhos para tarefas pequenas

Para tarefas obvias (renomear, ajuste de string, fix tipo), pule plan e revisao. So execute. Saber quando pular acelera o dia-a-dia.

⚡ Fast path (so DeepSeek, sem plano nem revisao)

  • • Renomear funcao/variavel em 1 arquivo
  • • Adicionar log/print debug
  • • Fix de typo
  • • Atualizar dependencia minor
  • • Mover funcao entre arquivos
  • • Adicionar campo em form trivial
6

🤖 Roteamento automatico

Algumas tools (Aider, Continue.dev) tem "auto-routing": detectam tipo de pergunta e escolhem modelo. Util quando setup amadurece.

🎛️ Regras de roteamento sugeridas

if (intent == "plan" || diff_size > 500) → GPT-5.5
else if (intent == "design" || file.includes("ui/")) → Opus
else if (intent == "implement" || intent == "test") → DeepSeek
else → DeepSeek (default)

Manual no inicio (voce aprende), automatico depois (reduz fadiga).
